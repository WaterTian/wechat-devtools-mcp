| **0.9.17** | **DevTools 2.x Stable support + function-style evaluate + speed-ups** (2026-09-03): WeChat DevTools 2.x has been the official Stable channel since 2026-08-18 (1.06 withdrawn); this release passed a full real-machine regression on Stable 2.02.2608060. **`fn_source` for evaluate** (full function source + `args_json`, mirroring the official `automation_evaluate`) and a root-cause fix for multi-statement `expression` silently running only the first statement (compile `return (code)` locally first; multi-statement input is a guaranteed SyntaxError and falls back to statement mode); returns `mode`. **Windows 1.x/2.x dual-runtime detection** via the official install-root.mjs probes (`code\package.nw` / `resources\app.asar.unpacked`); Electron uses the two-step open (not yet verified on a Windows machine). **`status` gains `official_mcp`**: a read-only heartbeat probe of the built-in MCP in IDE 2.x; when reachable the message suggests using official tools for basic operations while this project focuses on stitched screenshots, structured CDP logs and task-level SOPs. **Speed-ups**: `open` and `compile` now wait on readiness signals instead of fixed sleeps (poll process exit after kill, stop as soon as CDP listens, wait for mini-program targets then capture 3s, check pageStack immediately after compile); real-machine `open` went from ~28s to 7.6s. **Fixes**: `open` falls back to `WECHAT_PROJECT_PATH` when `project_path` is omitted (the second step of the 2.x two-step open was previously skipped and the project only appeared via IDE session restore); compile filters the new CLI's Node `punycode` deprecation noise; `start` re-runs `cli auto` (up to 3 rounds) when the port does not come up; `quit` waits for the process to actually exit and returns `exited`; config examples now register the server as `wechat-devtools-mcp` (DevTools 2.x registers its built-in bridge as `wechat-devtools`, and identical names get overridden); new "Relationship to WeChat's built-in capabilities" section. Tests 214 → 250, plus 4 Node scripts with 46 assertions |
| **0.9.16** | **Long-page screenshot overhaul + source code opened**: Fixed-region detection was rewritten from "find what did not change" to "find what moved". The old rule compared the two screenshots row by row and treated unchanged rows as fixed, which requires fixed elements to be **pixel-stable** — yet translucent/frosted nav bars show the scrolling content behind them, headers gain a shadow on scroll, and the status bar carries a ticking clock. Any of these fails from row 0, returns 0, and the nav bar gets stitched into every segment as content. The new rule uses the **known scroll distance** between the two shots: a row that can be located in the other image at `delta` offset is scrolling content — a defining property of content, independent of how it looks. Fixed elements no longer need to be stable, so the two legacy patches (`MAX_GAP`, `SAFE_AREA_SKIP`) are removed, each of which hard-coded one device/design assumption. Synthetic comparison (expected/old/new): translucent header 130/**0**/130, ticking clock 140/**20**/140, flat-color content 100/**200**/100 — the last is a previously unknown data-loss defect where flat-color content appears unchanged row by row and was swallowed whole as a fixed region. **Fixes long screenshots stopping after two viewports**: `waitForScrollComplete` returned as soon as two readings matched, so before `pageScrollTo` took effect both readings were the pre-scroll position and the caller concluded "bottom reached" (one list page captured only half its content). **Removes the gap between the first and second viewport** by starting with a conservative step and relaxing it once fixed regions are measured. **Fixes false truncation on lazy-loading lists**: the segment cap is now derived from the actual step and the page height is re-read each segment. **Incomplete or unreliable captures are no longer silent**: `is_scroll_view_page` / `truncated` / `content_gaps` / `detection_confident` were previously clamped away by `Math.max(0,...)` or dropped by `_ok()` on the Python side (the same class of defect as the v0.9.15 "CDP always returns 0 entries"); all are now surfaced and flagged with ⚠ in `message`, and `node_bridge` preserves the handler's `hint` on failure. Verified on real DevTools 2.x: help page `fixed_header` 0 → 166 with the duplicated nav bar gone (the old build also lost one item at the seam); a list page went from 3 segments/3184px to 7 segments/6815px; across 6 pages a band-match check confirms the header and footer each appear exactly once. **The source code is now open** ([#11](https://github.com/WaterTian/wechat-devtools-mcp/issues/11)): `src/` and 214 tests were merged into the public repo along with a new CONTRIBUTING.md; the `wechat_cloud` dead code, unregistered since v0.9.5, was removed |
| **0.9.15** | **DevTools 2.x (Electron) support + long-standing CDP capture fix**: WeChat DevTools 2.x switched from NW.js to Electron (1.06.x Stable is still NW.js, so both runtimes are supported rather than replaced). On macOS the launch path now detects the runtime by the presence of `Resources/package.nw` and reads the entry point from `CFBundleExecutable`, and the kill pattern uses the `.app` bundle path — the old pattern matched no Electron process, which made `wechat_ide(action='open')` with default arguments completely unusable on macOS. 2.x no longer honors the `--project` command-line flag, so the project is now opened by the CLI after the process starts with CDP, and only once both the CDP port and the IDE service port are listening (otherwise the CLI spawns a second instance without CDP, producing a "project opened but CDP unreachable" false success). **Fixes `wechat_inspector(action='cdp')` returning 0 entries ever since v0.9.0** — the daemon places results under `data` while the inspector read a non-existent `logs` key, silently disabling the most-used debugging tool for eight minor releases. The daemon stream limit is raised from asyncio's default 64 KiB to 16 MiB (a 6-second capture on 2.x measured 634 KiB; exceeding the limit silently discarded every result). CDP noise filtering now matches the 2.x target layout, excluding the new IDE shell pages and the `devtools://` target that slipped through because its type is `webview` (734 → 206 entries measured). IDE port detection now reads the `.ide` file the IDE writes on disk (the hard-coded candidate list never matches on 2.x); `status` gains `service_port_enabled` (the top cause of `CLI_TIMEOUT`, now self-diagnosing) and `ide_port`; `wechat_ide` and `wechat_build` gain a `cdp_port` parameter (9222 is frequently taken by Chrome) |
| **0.9.14** | **File-reading path fix + dead-parameter fix**: `wechat_file`'s `read_page`/`read_file` now resolve paths the same way `list_pages` does (try `miniprogramRoot` from `project.config.json` first, then fall back to the project root) — previously, in cloud-development projects the `pages/xxx/index` returned by `list_pages` always failed with "page files not found" when passed to `read_page`, breaking step 1 of SOP G; when the same filename exists under both roots, `also_found_at` now reports the unused path, and `project.config.json` always resolves to the authoritative copy at the project root; `read_page` returns `resolved_base` and `read_file` returns `resolved_path`. `wechat_inspector(action='cdp')` now forwards `cdp_port` (the parameter was previously inert and always connected to 9222). All `subprocess.CREATE_NO_WINDOW` references now use a `getattr` fallback, removing the `AttributeError` hazard on non-Windows platforms |
| **0.9.13** | **`--version` early exit + doc audit fixes**: `wechat-devtools-mcp --version` / `-V` prints the installed version and exits immediately with zero dependencies (uvx reuses installed environments without pulling latest, so one command confirms the actual version); doc fixes: navigate param table column misalignment, `设置 -> 安全设置` menu name, de-versioned `mcp_version` example; documented `wechat_ide` `result_output` and `wechat_navigate` `timeout` (undocumented since v0.6.0); SKILL.md Step 1 now includes a skill/MCP version consistency check |
